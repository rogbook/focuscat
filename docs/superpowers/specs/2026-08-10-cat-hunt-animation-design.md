# 집중 타이머 = 고양이 사냥 (설계)

날짜: 2026-08-10

## 왜

집중 시간이 흐르는 걸 숫자와 막대로만 보여주고 있다. 여기에 이야기를 붙인다 —
**집중이 진행되는 동안 고양이가 사냥을 준비하고, 시간이 끝나면 사냥에 성공한다.**
남은 시간을 보지 않아도 고양이 자세만으로 "얼마나 왔는지"가 읽힌다.

(아이디어: 오너의 아들)

## 무엇을 만드나

### 집중 화면 — 진행률에 따라 4단계

집중 길이와 무관하게 **진행률(`FocusTimer.progress`) 기준**으로 장면이 바뀐다.

| 진행률 | 장면 | 내용 |
|---|---|---|
| 0.00 ~ 0.35 | `watch` | 앉아서 나비를 보며 꼬리 살랑 |
| 0.35 ~ 0.65 | `aim` | 동공이 커지고 몸을 낮춤, 엉덩이 씰룩 |
| 0.65 ~ 1.00 | `stalk` | 살금살금 다가감 |
| 1.00 (완료 순간) | `pounce` | 앞발로 확 덮침. **2초간 1회 재생 후** 결과 화면으로 |

- 남은 시간 숫자와 진행 막대는 지금 그대로 둔다.
- 성장 단계(baby/teen/adult)별 사냥 장면은 만들지 않는다. 사냥은 한 종류.
  성장은 홈 화면 고양이가 이미 보여준다.
- 덮치기 2초 동안 "포기" 버튼은 눌리지 않게 잠근다.

### 결과 화면

- **성공**: 지금 그대로(기존 Rive 고양이). 사냥 연출은 집중 화면에서 끝난다.
- **실패**(포기·앱 이탈): `miss` — 나비를 놓치고 아쉬워하는 장면.
  나무라는 톤이 되지 않게, 아쉬움 정도로만.

### 홈 화면

건드리지 않는다. 기존 `CatView`(Rive) 그대로.

## 애셋

힉스필드에서 영상 5개를 뽑고, WebP 애니메이션으로 변환해 앱에 넣는다.

| 파일 | 장면 | 반복 |
|---|---|---|
| `assets/hunt/watch.webp` | 꼬리 살랑 | 무한 |
| `assets/hunt/aim.webp` | 동공 확대·자세 낮춤 | 무한 |
| `assets/hunt/stalk.webp` | 살금살금 | 무한 |
| `assets/hunt/pounce.webp` | 덮치기 | 1회 |
| `assets/hunt/miss.webp` | 놓치고 아쉬워함 | 무한 |

생성 규격:

- 길이 2~3초, 정사각형
- **배경은 단색 `#F0F4F3`** (앱 배경색 `kBg`와 같게). 투명 배경 대신 배경색을
  맞춰서 화면에 자연스럽게 얹는다.
- 사냥감은 **나비**. 쥐·새는 잡는 순간이 잔인해 보이고, 나비는 팔랑거려서
  "꼬리 살랑 → 조준 → 살금살금"이 자연스럽게 붙는다.
- **기존 고양이를 참고 이미지로 넣는다.** 안 넣으면 집중 화면 고양이만 다른
  그림체가 되어 다른 고양이처럼 보인다.

변환:

- 힉스필드 mp4 → 움직이는 WebP (ffmpeg)
- 반복 장면(`watch`/`aim`/`stalk`)은 **앞으로 갔다 뒤로 오는 방식**으로 이어
  붙여 끊김 없이 돌게 만든다. AI 영상은 첫 프레임과 끝 프레임이 달라서 그냥
  반복하면 튄다.
- 목표 용량: 5개 합쳐 2MB 안쪽. 넘으면 해상도(가로 400px 기준)와 프레임 수를
  줄인다.
- `pounce`만 **1회 재생**으로 인코딩한다(`img2webp -loop 1`). 어차피 2초 뒤
  화면이 넘어가므로, 플러터가 반복 횟수를 안 지키더라도 티가 나지 않는다.
- `miss`는 **무한 반복**으로 만든다. 결과 화면에 계속 떠 있는 그림이라
  한 번 재생하고 멈추면 어색하다. 그래서 "나비를 놓치는 동작"이 아니라
  **놓친 뒤 아쉬워하며 꼬리를 툭툭 치는, 그 자체로 반복되는 장면**으로 만든다.
  (이러면 플러터의 반복 처리 방식에 기대지 않아도 된다.)

## 왜 WebP인가

플러터의 `Image.asset`이 움직이는 WebP를 **그대로 재생한다.** 새 패키지가 필요
없다.

- mp4 + `video_player`: 화질은 좋지만 부품이 늘고, 25분 내내 영상 재생기를
  돌리는 배터리·발열 부담이 있다.
- 정지 그림 4장: 제일 가볍지만 "꼬리 흔들기·살금살금"이 죽는다. 아이디어의
  핵심이 움직임이라 탈락.

## 코드 구조

새 파일 하나 + 기존 파일 두 곳 수정. 새 의존성 없음.

### `lib/hunt.dart` (새 파일)

```
enum HuntPhase { watch, aim, stalk, pounce, miss }

// 진행률 → 단계. 순수 함수, 플러터를 모른다. 테스트 대상.
HuntPhase huntPhaseFor(double progress)

// 단계 하나를 그리는 위젯. Image.asset 한 장.
class HuntView extends StatelessWidget
```

`huntPhaseFor`는 `watch`/`aim`/`stalk` **셋만** 돌려준다. 진행률 1.0도 `stalk`다
— 덮치기는 "시간이 다 됐다"는 사건이지 진행률이 아니고, `miss`도 마찬가지다.
둘은 호출부에서 직접 지정한다. 순수 함수로 떼어내면 경계값을 위젯 없이
테스트할 수 있다.

### `lib/screens.dart` 수정

- `FocusScreen`: `CatView` → `HuntView(phase: huntPhaseFor(_timer.progress))`
- `FocusScreen._finish()`: 성공으로 끝났으면 `pounce`를 2초 보여준 뒤 결과
  화면으로. 그동안 포기 버튼 비활성화.
  - 포기·이탈로 끝난 경우는 지금처럼 곧바로 넘어간다.
  - 화면이 이미 사라진 경우(`_abandonSilently`)는 영향 없음.
- `ResultScreen`: 실패일 때 `CatView(mood: sad)` → `HuntView(phase: miss)`.
  성공일 때는 그대로.

### `pubspec.yaml`

`assets/hunt/` 디렉터리 추가.

## 확인 방법

- `test/hunt_test.dart` — `huntPhaseFor`의 경계값. 0, 0.34, 0.35, 0.64, 0.65,
  0.99, 1.0에서 기대한 단계가 나오는지.
- 실제 확인은 시뮬레이터에서: 짧은 집중(1분)으로 4단계가 다 넘어가는지, 끝날 때
  덮치기가 2초 보이고 결과 화면으로 넘어가는지, 포기했을 때 놓침 장면이 뜨는지.

## 안 하는 것

- 성장 단계별 사냥 장면 (3배 작업량, 지금 필요 없음)
- 성공 결과 화면의 전리품 장면 (애셋 하나 더. 써 보고 아쉬우면 그때)
- 사냥 소리 효과 (배경음이 이미 있다)
- reduce-motion 대응 (반복 애니메이션이라 위험하진 않다. 요청 오면 정지
  프레임으로 대체)
